# PMS-X 설치 가이드 (오프라인 패키지)

> 대상: 고객사 납품형 On-prem, 인터넷이 차단된 서버 포함. 패키지 하나(`pmsx-<버전>-offline.zip`)에 실행에 필요한 것이 모두 들어 있다.

## 1. 패키지 구성

| 경로 | 내용 |
|---|---|
| `pmsx-server.jar` | 서버 + 웹 화면(단일 jar). 웹은 같은 주소에서 제공된다 |
| `jre/` | 동봉 Java 21 런타임 (Windows x64 빌드. Linux 패키지는 빌드 시 `--jdk` 로 Linux JDK 지정) |
| `bin/start.bat` · `stop.bat` · `start.sh` · `stop.sh` | 시작·종료 스크립트 (운영) |
| `bin/start-demo.bat` · `start-demo.sh` | **시연용** 시작 스크립트 (아래 3-1절). 종료는 `stop` 과 같다 |
| `demo/` | 시연용 As-Is 수집 결과 (인사·급여·교육 샘플 시스템) |
| `lib/` | 추가 JDBC 드라이버 (Tibero 등 — 아래 3-2절) |
| `config/application-prod.yml` | 운영 설정 (DB·포트·LDAP 등). `config/examples/` 에 H2 예시 |
| `nginx/pmsx.conf` | HTTPS 리버스 프록시 예시 |
| `docker/` | Dockerfile·docker-compose (⚠ 미검증 — 아래 7절) |
| `license-tool/` | 라이선스 키 확인 도구, 개발용 공개키·라이선스 |
| `run/` `logs/` `data/` | PID·임시 파일 / 로그 / 첨부·캡처·내장 DB (시연용은 `data-demo/`) |

## 2. 사전 준비
- OS: Windows Server 2016 이상 또는 Linux x64 (RHEL 8+, Ubuntu 20.04+)
- 메모리 4GB 이상(서버 힙 기본 2GB), 디스크: 수집 캡처 이미지 규모에 따라 20GB~
- DB(저장소): **PostgreSQL 13+ (권장)**, **Oracle 12c+ (19c 기준, 11g R2 는 ROWNUM 페이징 옵션)**, **Tibero 6/7**, **SQL Server 2016+**. 시범·소규모는 내장 H2. → 3-2절
- 포트: 8080(기본). HTTPS 는 nginx 등 리버스 프록시에서 종단

## 3. 설치
1. zip 을 설치 폴더에 푼다. 예) `D:\pmsx`, `/opt/pmsx` (경로에 공백이 있어도 된다)
2. DB 준비 — PostgreSQL 예 (Oracle·Tibero·SQL Server 는 3-2절):
   ```sql
   CREATE USER pmsx WITH PASSWORD '********';
   CREATE DATABASE pmsx OWNER pmsx ENCODING 'UTF8';
   ```
   테이블은 최초 기동 시 자동 생성된다(Flyway, Tibero 는 내장 실행기). DB 종류는 접속 URL 로 자동 판별한다.
3. `config/application-prod.yml` 수정 — DB 주소·계정, HTTPS 여부(`cookie-secure`), LDAP.
   비밀번호는 파일 대신 환경 변수로 줄 수 있다: `PMSX_DB_PASSWORD`, `PMSX_LDAP_BIND_PASSWORD`.
   - 내장 H2 로 바로 써 보려면: `config/examples/application-prod-h2.yml` 내용을 `config/application-prod.yml` 에 덮어쓴다.
4. 시작
   - Windows: `bin\start.bat`  /  Linux: `bin/start.sh`
   - 로그: `logs/pmsx.log` (시작 실패는 `logs/console.log`)
5. 최초 관리자 로그인
   - 사용자가 한 명도 없으면 `admin` 계정이 자동 생성되고 비밀번호가 `run/initial-admin-password.txt` 에 기록된다.
   - (미리 정하려면 최초 기동 전에 환경 변수 `PMSX_ADMIN_PASSWORD` 지정)
   - 로그인 후 **비밀번호를 바꾸고 이 파일을 삭제**한다.
6. 라이선스 적용 — 관리 › 라이선스·시스템 정보에서 발급받은 키를 붙여넣는다.
   - 라이선스가 없거나 만료되면 **시스템 관리자만** 로그인할 수 있다.
7. 종료: `bin\stop.bat` / `bin/stop.sh`

## 3-1. 시연용 실행 (데모)
설치·DB 준비 없이 기능을 둘러보려면 시연용 스크립트를 쓴다. 운영 데이터와 완전히 분리된다.

- 시작: Windows `bin\start-demo.bat` / Linux `bin/start-demo.sh` → 브라우저에서 `http://<서버>:8080`
- 종료: `bin\stop.bat` / `bin/stop.sh` (운영과 같은 스크립트, 동시에 둘 다 띄우지 않는다)
- 프로필 `demo`: 내장 H2 DB 를 `data-demo/` 에 만들고 최초 기동 시 데모 데이터를 자동으로 채운다.
  - SI 프로젝트 "○○공사 차세대 SI": `demo/*.zip` 수집 결과(인사 HR·급여 PY·교육 ED) 적재, 분석 상태·메모·핫스팟 결함, WBS·인력·품질 데이터
  - SM 프로젝트 "○○공사 인사시스템 운영(SM)": 인사시스템을 인수인계해 만든 운영 프로젝트, SR·장애·변경·KB·SLA 데이터
- 데모 계정 (비밀번호 모두 `pmsx1234!`): `admin`(관리자·PM), `analyst`(분석자), `customer`(고객 SR 포털)
- 처음 상태로 되돌리기: 종료 후 `data-demo/` 폴더 삭제 → 다시 시작
- ⚠ 시연 전용이다. 공개된 비밀번호·개발용 JWT 키를 쓰고 라이선스 검사를 하지 않으므로 운영에 쓰지 않는다.

## 3-2. 저장소 DB 별 설정
`config/application-prod.yml` 의 `spring.datasource` 만 바꾸면 된다(DB 종류 자동 판별, 필요하면 `pmsx.db.vendor` 로 지정).
DB 계정은 **PMS-X 전용 스키마 소유자**로 만들고, 최초 기동 시 테이블·인덱스가 자동 생성된다.

| DB | 접속 URL 예 | 준비 |
|---|---|---|
| PostgreSQL 13+ | `jdbc:postgresql://db:5432/pmsx` | `CREATE DATABASE pmsx ENCODING 'UTF8'` |
| Oracle 12c+ (19c) | `jdbc:oracle:thin:@//db:1521/ORCLPDB1` | 아래 Oracle |
| Oracle 11g R2 | 위와 같음 + `pmsx.db.legacy-paging: true` | ROWNUM 페이징 |
| Tibero 6/7 | `jdbc:tibero:thin:@db:8629:tibero` + `driver-class-name: com.tmax.tibero.jdbc.TbDriver` | 드라이버 jar 를 `lib/` 에 (`lib/README.txt`) |
| SQL Server 2016+ | `jdbc:sqlserver://db:1433;databaseName=pmsx;encrypt=true;trustServerCertificate=true` | 아래 SQL Server |

**Oracle · Tibero**
```sql
-- DB 문자셋: AL32UTF8 권장 (KO16MSWIN949 도 동작하지만 한글 외 문자 저장 제한)
CREATE USER PMSX IDENTIFIED BY "********" DEFAULT TABLESPACE USERS QUOTA UNLIMITED ON USERS;
GRANT CREATE SESSION, CREATE TABLE TO PMSX;     -- 인덱스·제약은 자기 스키마이므로 추가 권한 불필요
```
- Oracle 은 빈 문자열을 NULL 로 저장한다. PMS-X 는 이를 고려해 일부 본문 컬럼(메모·코멘트 등)을 NULL 허용으로 만들며, 빈 값은 화면에서 비어 있게 보인다.
- Tibero 는 Flyway 를 지원하지 않아 PMS-X 내장 마이그레이션 실행기가 `PMSX_SCHEMA_HISTORY` 테이블로 버전을 관리한다. 페이징은 ROWNUM 방식이 기본이다.

**SQL Server**
```sql
-- 반드시 대소문자를 구분하는(_CS_) 데이터 정렬로 만든다 (수집 키·함수명이 대소문자를 구분)
CREATE DATABASE pmsx COLLATE Korean_100_CS_AS;
CREATE LOGIN pmsx WITH PASSWORD = '********';
USE pmsx; CREATE USER pmsx FOR LOGIN pmsx; ALTER ROLE db_owner ADD MEMBER pmsx;   -- 또는 db_ddladmin + db_datareader + db_datawriter
```
- `_CI_`(대소문자 미구분) 데이터 정렬이면 기동 시 안내와 함께 중단한다(`pmsx.db.allow-case-insensitive: true` 로 강제 가능 — 권장하지 않음).
- SQL Server 구성 관리자에서 **TCP/IP 프로토콜**을 켜고 포트(기본 1433)를 열어야 한다(JDBC 는 TCP 만 사용).
- 수집 키 유니크 인덱스(AS_EDGE·AS_RELATION)는 최대 키 길이 1700바이트 경고가 난다. 키가 매우 긴(수백 자) 경우에만 저장 오류가 날 수 있다.

**검증 범위 (1.1.0)**: PostgreSQL·H2 는 실DB, SQL Server 는 실DB(SQL Server 2022, 테스트 시나리오 SQL 1.6만 건 재생)로 확인했다.
Oracle·Tibero 는 실DB 없이 H2 Oracle 호환 모드 통합 테스트 + Oracle 문법 정적 검사로 확인했으므로, 도입 전 고객사 DB 로 기동해 아래 10절 점검표대로 확인하기를 권장한다.

## 4. 보안 기본값
- JWT 서명 키: 설정을 비워 두면 최초 기동 시 `data/jwt-secret.key` 를 자동 생성한다(설치마다 다른 키). 파일 권한을 서비스 계정만 읽게 제한한다.
- 비밀번호 정책: 9자 이상, 영문·숫자·특수문자 포함, 직전 비밀번호 재사용 불가, 5회 실패 시 잠금
- Swagger(API 문서)는 운영에서 꺼져 있다 (`PMSX_SWAGGER=true` 로 켤 수 있음)
- 감사 로그: 로그인·다운로드·소스 조회·관리 변경이 기록된다 (관리 › 감사 로그)

## 5. LDAP / AD 연동
`config/application-prod.yml` 의 `pmsx.auth.ldap` 을 설정한다.
- AD: `user-search-filter: (sAMAccountName={0})`, OpenLDAP: `(uid={0})`
- 관리 › 사용자에서 인증 방식 **LDAP** 으로 사용자를 먼저 등록해야 로그인할 수 있다(자동 가입 없음).

## 6. HTTPS (nginx)
`nginx/pmsx.conf` 를 참고해 TLS 를 종단하고 `http://127.0.0.1:8080` 으로 넘긴다. 업로드 한도 300MB.
HTTPS 로 운영하면 `cookie-secure: true` 를 유지한다.

## 7. Docker (선택, ⚠ 미검증)
빌드 환경에 Docker 가 없어 `docker/` 의 파일은 **실제 빌드·실행 검증을 하지 않았다.** 사용 시 인터넷 되는 곳에서 이미지를 만들어 `docker save` → 고객망에서 `docker load` 한다. 절차는 `docker/Dockerfile` 머리 주석 참고.

## 8. 백업·업그레이드
- 백업 대상: DB(`pg_dump pmsx`), `data/` 폴더(첨부·캡처·내장 DB·jwt 키), `config/`
- 업그레이드: 종료 → `pmsx-server.jar`(+ 필요 시 `jre/`) 교체 → 시작. DB 변경은 기동 시 자동 적용(Flyway). **업그레이드 전 백업 필수.**

## 9. Windows 서비스로 등록 (권장)
`start.bat` 은 콘솔 세션에 묶여 있으므로 운영에서는 서비스 래퍼(WinSW, NSSM 등 고객사 허용 도구)로 `jre\bin\java.exe -jar pmsx-server.jar --spring.profiles.active=prod --spring.config.additional-location=optional:file:./config/` 를 등록하고, 작업 폴더를 설치 폴더로, 환경 변수 `PMSX_HOME` 을 설치 폴더로 지정한다.
`stop.bat` 은 프로세스를 강제 종료하므로, 서비스 래퍼의 정상 종료(Ctrl+C 신호)를 쓰는 편이 안전하다.

## 10. 문제 해결
| 증상 | 확인 |
|---|---|
| 시작 직후 종료 | `logs/console.log` — DB 접속 실패, 포트 사용 중(8080) |
| 일반 사용자 로그인 시 "라이선스가 유효하지 않아…" | 관리자로 로그인해 라이선스 확인(만료·사용자 수 초과) |
| 계정 잠김 | 관리 › 사용자에서 잠금 해제 또는 비밀번호 초기화 |
| 업로드 실패 "파일이 너무 큽니다" | nginx `client_max_body_size`, 첨부는 `PMSX_FILE_MAX_SIZE`(기본 50MB) |
| "데이터 정렬(…_CI_…)이 대소문자를 구분하지 않습니다" | SQL Server DB 를 `_CS_` 데이터 정렬로 다시 만든다 (3-2절) |
| SQL Server 접속 실패 (TCP/IP 연결 거부) | SQL Server 구성 관리자 › 네트워크 구성 › TCP/IP 사용, 서비스 재시작, 방화벽 1433 |
| Tibero `ClassNotFoundException: com.tmax.tibero.jdbc.TbDriver` | `lib/` 에 Tibero JDBC jar 가 있는지, `bin/start` 로 기동했는지(loader.path) |
| `ORA-01950: no privileges on tablespace` | Oracle 계정에 테이블스페이스 QUOTA 부여 |
| Oracle·Tibero 도입 전 점검 | 고객사 DB 로 `bin/start` 기동 후 로그인 → 수집 결과 업로드 → 화면 분석 뷰어·WBS·SR 화면 조회가 오류 없이 되는지 확인 |
