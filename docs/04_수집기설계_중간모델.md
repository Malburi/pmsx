# 04. 수집기(pmsx-collector) 설계 · 중간모델

- 문서 버전: v0.1 (2026-10-14)
- JSON 스키마: [`schema/asis-model.schema.json`](schema/asis-model.schema.json)
- 관련 요구사항: FR-CL-001 ~ 022, NFR-SEC-001·002

## 1. 실행 환경
- **고객망 내부**의 분석용 PC/서버에서 실행 (Windows 권장 — WinForms·구형 런타임 캡처에 필요).
- 배포: Python + PyInstaller **단일 실행파일** `pmsx-collector.exe` + 오프라인 Playwright 브라우저 번들.
- 입력: 수집 설정 YAML, 소스 경로(읽기), DB 읽기 전용 계정, 테스트계 URL·테스트 계정.
- 출력: 결과 패키지 `pmsx-<system>-<회차>.zip` = `model.json` + `captures/*.png` + `report.html`.
- 반입: 서버에 HTTP 업로드(망 연결 시) 또는 파일 반입 후 SCR-AS-004에서 업로드.

### ② 동적 캡처 안전 규칙 (기본값, 끌 수 없음 표시 ★)
1. ★ 변경성 요청 차단: `POST/PUT/PATCH/DELETE`는 **요청 내용을 기록한 뒤 abort**. 단 설정의 `allowRequests`(조회성 POST 패턴, 예: `*/list.do`, `*/select*.do`)에 해당하면 통과.
2. 위험 버튼 클릭 제외: 라벨/ID에 `삭제|저장|등록|승인|결재|전송|발송|확정|마감|del|save|apprv` 포함 시 클릭하지 않음 → 정적 분석으로만 연결(신뢰도 낮게).
3. `window.open`·팝업은 캡처 후 닫음, `alert/confirm`은 자동 '취소' 응답(취소 경로로 진행해 서버 호출 방지).
4. 메뉴당 타임아웃, 실패 화면은 리포트에 남기고 계속 진행.
5. ★ 운영계 URL 차단 목록(`denyHosts`)과 일치하면 실행 거부.

### ③ 정적 분석 — 파서 플러그인
모든 파서는 같은 인터페이스를 구현하고 중간모델 조각을 반환한다.

```python
class Parser(Protocol):
    name: str                      # "jsp-jquery", "nexacro", "spring-mybatis", ...
    layer: Literal["ui", "server", "sql", "db"]
    def detect(self, root: Path) -> float: ...          # 이 경로에 적용 가능성(0~1)
    def parse(self, root: Path, ctx: Context) -> ModelFragment: ...
```

| 파서 | 레이어 | 추출 대상 | 엔진 |
|---|---|---|---|
| `jsp-jquery` | ui | 요소(id/name/label), `onclick`, `$(sel).on/click`, `$.ajax/gfn_ajax` URL, `form action`, `window.open` | HTML 파서 + tree-sitter(JS) |
| `nexacro` | ui | XFDL 컴포넌트·좌표·이벤트, `transaction()` 서비스ID·in/out Dataset | XML + tree-sitter(JS) |
| `websquare` | ui | 화면 XML 컴포넌트, submission 정의 | XML |
| `miplatform-xplatform` | ui | XML 화면 정의·스크립트 트랜잭션 | XML |
| `vue` / `react` | ui | router, 컴포넌트 `@click`/`onClick`, API 모듈 호출 | tree-sitter(TS/JS) + SFC 파서 |
| `winforms` | ui | `*.Designer.cs` 컨트롤·Location/Size·`Click +=` 핸들러 | tree-sitter(C#) |
| `aspnet` | ui+server | `.aspx` `OnClick=`, code-behind, MVC Razor·Controller | HTML + tree-sitter(C#) |
| `spring` | server | `@RequestMapping/@GetMapping…` → 메서드 호출 그래프 | tree-sitter(Java) |
| `mybatis-ibatis` | sql | Mapper XML(namespace.id) ↔ 인터페이스, 동적 SQL 정규화 | XML + SQL 파서 |
| `dotnet-data` | sql | ADO.NET `CommandText`, Dapper, EF, SP 호출 | tree-sitter(C#) |
| `sql` | sql/db | SQL 문 → 테이블·컬럼·CRUD, PL/SQL·T-SQL SP 본문 | SQL 파서(sqlglot) |
| `harness` | 전체 | 기존 `_workspace/**/*.json`(schema·sql_usage·call_graph) 변환 | JSON |

### ④ 병합·매칭
- **요소 매칭 (동적 ↔ 정적)**: ① id 일치 → ② name 일치 → ③ 라벨 텍스트 + 타입 일치 → ④ 좌표 근접(Nexacro·WinForms는 소스에 좌표가 있음). 실패 시 `unmatched=true`.
- **API 매칭 (프론트 ↔ 서버)**: URL 정규화(컨텍스트 경로 제거, `{id}`·쿼리 제거) 후 서버 매핑과 비교. 동적으로 실제 요청이 관측되면 `source=dynamic, confidence=1.0`.
- **신뢰도 기준(초안)**: 동적 관측 1.0 / 정적 직접 호출 0.95~0.99 / 문자열 조합 URL 추정 0.7~0.85 / 이름 유사 추정 0.5.

### 추정 관계 (FK 없는 레거시)
SQL의 `JOIN … ON A.x = B.y`, `WHERE A.x = B.y` 를 모아 (테이블쌍, 컬럼쌍) 빈도를 센다. 한쪽 컬럼이 PK/유니크면 방향 결정. `빈도 ≥ 3` 이면 후보로 출력하고 confidence = 빈도·PK 여부·컬럼명 일치도로 계산. 뷰어 ERD에서 확정/기각.

## 4. 중간모델 개요
모든 객체는 **안정 키(key)** 를 가진다. 재수집해도 같은 대상이면 같은 키 → 회차 간 변경 비교·수동 보정 유지에 사용.

| 객체 | 키 형식 | 예 |
|---|---|---|
| system | `sys:<code>` | `sys:HR` |
| menu | `menu:<sys>:<menuId>` | `menu:HR:M0101` |
| screen | `scr:<sys>:<screenId>` | `scr:HR:HR0101` |
| element | `el:<screenKey>#<elementId>` | `el:HR:HR0101#btnSave` |
| codeUnit | `fn:<lang>:<file>#<name>` | `fn:js:/js/hr/HR0101.js#fn_save` |
| api | `api:<METHOD> <path>` | `api:POST /hr/emp/save.do` |
| sql | `sql:<namespace>.<id>` 또는 `sp:<schema>.<name>` | `sql:EmpMapper.insertEmp` |
| table | `tbl:<schema>.<name>` | `tbl:HR.TB_EMP` |

연결은 모두 `edges[]` 하나로 표현한다: `{from, to, kind, source, confidence, crud?, columns?}`
- `kind`: `event`(요소→함수) · `calls`(함수→함수) · `request`(함수→API) · `handles`(API→서버함수) · `executes`(함수→SQL) · `accesses`(SQL→테이블, crud 포함) · `navigates`(함수/요소→화면) · `binds`(요소→테이블.컬럼)
- `source`: `static` · `dynamic` · `manual`

뷰어의 워크플로우는 `el:…` 에서 시작해 edges를 따라 내려가며 그린다. 수동 보정(`manual`)은 서버 DB에 별도 보관하고, 재수집 시 같은 키에 다시 덮어 적용한다.

## 5. harness `_workspace` 연계
| harness 파일 | 매핑 |
|---|---|
| `schema*.json` | `tables[]`, `columns[]`, FK → `relations[]` |
| `sql_usage*.json` | `sqlStatements[]` + `accesses` edges |
| `call_graph*.json` | `codeUnits[]` + `calls`/`handles` edges |
| publish-wiki `api_endpoints` / `frontend_routes` | `apis[]`, 메뉴·화면 보조 정보 |

정확한 필드 매핑은 R1 착수 시 실제 harness 산출물 샘플로 확정한다.

## 6. 실행 리포트 (`report.html`)
메뉴 수·화면 수, 캡처 성공/실패(사유), 요소 수·매칭률, 이벤트→API 연결률, API→SQL 연결률, **차단된 요청 목록**, 위험 버튼으로 클릭 제외된 목록, 추정 관계 후보 수, 소요 시간.
