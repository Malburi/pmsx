# 03. As-Is 화면 분석 뷰어 화면 설계 (SCR-AS-001)

- 문서 버전: v0.1 (2026-10-14)
- 클릭 가능한 목업: [`mockup/asis-viewer.html`](mockup/asis-viewer.html) — 브라우저로 열기. 샘플 화면은 `HR0101 사원관리`.
- 관련 요구사항: FR-AS-002 ~ 016, 019 ~ 022, 027

## 1. 화면 목적
분석자·개발자·운영자가 **"이 화면의 이 버튼을 누르면 무슨 일이 일어나는가"** 를 소스를 열지 않고 한 화면에서 파악한다.
- SI 분석 단계: As-Is 현행 분석, 화면정의서·프로그램 사양서 작성의 원천
- SI 개발/시험: 변경 영향 파악, 결함을 화면 요소에 직접 등록
- SM 운영: SR 대상 화면을 열어 처리 흐름·테이블을 즉시 확인

## 2. 레이아웃 (3단 분할)

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ GNB: 프로젝트 선택 · 경로 · 사용자                                            │
├───────────────┬─────────────────────────────────────┬────────────────────────┤
│ ① 메뉴 트리    │ ② 화면 헤더: 화면명·ID·상태·담당·캡처일 │ ④ 요소 상세 패널        │
│  - 검색        │ ③ 탭: 캡처 | 컴포넌트 | 이벤트 | CRUD   │  - 요소 정보            │
│  - 시스템>메뉴 │   ┌ 범례 · 필터(버튼만/번호숨김) ┐      │  - 탭: 워크플로우       │
│    >화면(팝업) │   │ 화면 캡처 + 핫스팟 오버레이   │      │        사용 테이블      │
│  - 상태 점     │   │ (번호 배지, 타입별 색)        │      │        연결 이력·메모   │
│ 분석 진척 바   │   └──────────────────────────────┘      │  - 소스 스니펫          │
└───────────────┴─────────────────────────────────────┴────────────────────────┘
  폭: 260px          가변                                   420px (리사이즈 가능)
```
- 1100px 미만: 세로 스택(트리 → 캡처 → 상세).

## 3. 영역별 상세

### ① 메뉴 트리
| 항목 | 설명 |
|---|---|
| 검색 | 화면명/ID, 버튼 라벨/ID, 함수명, API URL, 테이블명. 결과 클릭 시 화면 이동 + 해당 요소 자동 선택 |
| 노드 | 시스템 › 메뉴(다단계) › 화면 › 팝업. 화면 노드 앞 상태 점: 회색 자동수집 / 주황 검토중 / 초록 확정 |
| 하단 | 선택 시스템의 분석 진척(확정 화면 수 / 전체) |
| 우클릭 | 담당자 지정, 상태 변경, 화면정의서 출력 |

### ② 화면 헤더
화면명, 화면 ID, 분석 상태 칩, 메뉴 경로, 화면/서버 기술, 담당자·검토자, 캡처 회차·일시, [상태 변경] [검토 요청] [산출물 출력] 버튼.

### ③ 중앙 탭
| 탭 | 내용 |
|---|---|
| **캡처** | 실제 캡처 이미지 + 핫스팟. 확대/축소(휠), 화면 맞춤. 요소 타입별 색: 버튼 파랑·입력 초록·콤보 보라·그리드 주황·팝업호출 분홍. 점선 = 핸들러 미매칭. 마우스 오버 시 툴팁(라벨·ID·핸들러) |
| 컴포넌트 목록 | 번호·ID·라벨·타입·바인딩·이벤트 수. 행 클릭 = 핫스팟 선택. 엑셀 출력 |
| 이벤트 목록 | 요소·이벤트·핸들러·호출 API·사용 테이블(CRUD) 요약 |
| CRUD | 요소 × 테이블 C/R/U/D 매트릭스 |
| (편집 모드) | 권한자만. 핫스팟 드래그 추가/이동/크기 조절, 요소 ↔ 핸들러 매칭 지정, 개인정보 영역 마스킹 |

### ④ 요소 상세 패널
**요소 정보**: 번호·라벨·타입, 요소 ID, 바인딩(Dataset/컬럼/모델), 이벤트 → 핸들러, 좌표.

**워크플로우 탭** (핵심)
- 세로 흐름도, 노드마다 레이어 표시: `화면 → 프론트 → API → 서버 → SQL → 테이블 → 후처리`
- 노드: 제목(함수/URL/SQL ID/테이블명) + 부제(파일:라인, 파라미터, 사용 컬럼). 테이블 노드에 C/R/U/D 배지
- 연결선: 출처 배지(정적/동적/수동) + 신뢰도. 90% 미만 또는 미확정은 점선
- 분기: 검증 실패·확인 취소 같은 조기 종료는 옆 가지로 표시(R1)
- 다른 흐름 재사용: "fn_search() 호출" 처럼 다른 버튼 흐름을 부르면 링크로 이동
- 노드 클릭 → 아래 **소스 스니펫**(파일 경로·라인·언어, 문법 강조, 원본 열기)
- 이벤트가 여러 개면 상단에 이벤트 선택 칩

**사용 테이블 탭**: 테이블별 CRUD·사용 컬럼, 관계(FK 확정 / 추정 + JOIN 횟수) 미니 ERD, 테이블 정의서로 이동.

**연결 이력·메모 탭**: 연결된 요구사항·SR·결함·테스트·CR, 업무 규칙 메모(작성자·일시), 분석 이력(수집 회차, 상태 변경, 보정 내역).

## 4. 주요 시나리오
1. **분석자 – 화면 분석 확정**: 트리에서 화면 선택 → 미매칭(점선) 요소 확인 → 편집 모드에서 핸들러 지정 → 버튼별 메모 작성 → [검토 요청] → 검토자 확정.
2. **개발자 – 변경 영향 확인**: 검색에 `TB_EMP` 입력 → 사용하는 화면·버튼 목록 → 각 버튼 워크플로우에서 CRUD 확인.
3. **운영자 – SR 처리**: SR 상세의 "대상 화면" 링크 → 뷰어가 해당 버튼 선택 상태로 열림 → 워크플로우·SQL 확인 → 처리 후 메모 남김.
4. **PM – 산출물**: 확정된 화면 일괄 선택 → 화면정의서(캡처+요소표+이벤트표) 엑셀/PPT 출력.

## 5. 화면 구현 메모
- 핫스팟: 캡처 이미지 위 절대 좌표 레이어(SVG 또는 div). 좌표는 수집 해상도 기준이고 표시 배율에 맞춰 환산.
- 워크플로우: `CALL_EDGE` 그래프를 이벤트 기준으로 잘라 내려가며 그린다(깊이 제한 기본 8, 공통함수는 접기). 복잡한 분기는 Vue Flow + elkjs 레이아웃.
- 소스 스니펫: 수집 시 함수 단위로 잘라 저장(원본 전체 반입 여부는 고객사 보안 정책에 따라 선택).
- 성능: 화면 진입 시 요소·이벤트 요약만 받고, 워크플로우·소스는 요소 선택 시 따로 받는다.
